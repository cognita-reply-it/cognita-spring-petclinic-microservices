## Build and deployment units

The [root POM](../../pom.xml) is a Maven reactor with eight executable child JARs, Java 17, Spring Boot 4.0.1 and Spring Cloud 2025.1.0. There is no shared domain-library module. Cross-service DTOs are local copies: coordinate producer, gateway, UI and GenAI consumers when fields change. [Maven wrapper configuration](../../.mvn/wrapper/maven-wrapper.properties) selects Maven 3.9.8.

All paths in this table start at repository root. Ports are the mappings declared by [Compose](../../docker-compose.yml), not independently observed listeners. Except Config Server's local 8888 setting, runtime configuration must be reconciled with external Config Server properties.

| Module / entrypoint | Responsibility and dependencies | Compose port |
|---|---|---|
| [config-server](../../spring-petclinic-config-server/src/main/java/org/springframework/samples/petclinic/config/ConfigServerApplication.java) | Spring Cloud Config; external Git configuration or explicitly selected native backend | 8888 |
| [discovery-server](../../spring-petclinic-discovery-server/src/main/java/org/springframework/samples/petclinic/discovery/DiscoveryServerApplication.java) | Eureka registry; imports Config Server configuration | 8761 |
| [customers-service](../../spring-petclinic-customers-service/src/main/java/org/springframework/samples/petclinic/customers/CustomersServiceApplication.java) | Spring MVC/JPA; owns owners, pets and pet types; Config/Eureka clients | 8081 |
| [visits-service](../../spring-petclinic-visits-service/src/main/java/org/springframework/samples/petclinic/visits/VisitsServiceApplication.java) | Spring MVC/JPA; owns visits keyed by pet ID; Config/Eureka clients | 8082 |
| [vets-service](../../spring-petclinic-vets-service/src/main/java/org/springframework/samples/petclinic/vets/VetsServiceApplication.java) | Spring MVC/JPA; vets and specialties; cached reads; Config/Eureka clients | 8083 |
| [genai-service](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/GenAIServiceApplication.java) | Chat endpoint, provider tools and vector retrieval; Config/Eureka, customers and vets dependencies | 8084 |
| [api-gateway](../../spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/ApiGatewayApplication.java) | Reactive Spring Cloud Gateway, owner/visit aggregation and static UI; Config/Eureka clients | 8080 |
| [admin-server](../../spring-petclinic-admin-server/src/main/java/org/springframework/samples/petclinic/admin/SpringBootAdminApplication.java) | Spring Boot Admin operational UI; Config/Eureka clients; [POM](../../spring-petclinic-admin-server/pom.xml) pins Admin 4.0.2 | 9090 |

[GenAI's POM](../../spring-petclinic-genai-service/pom.xml) pins Spring AI 2.0.0-M1 and enables the OpenAI starter; the Azure starter is commented out. Its [configuration](../../spring-petclinic-genai-service/src/main/resources/application.yml) explicitly selects reactive mode despite also declaring MVC/JPA dependencies. Dependency presence is not proof of a used persistence path: GenAI source uses a `SimpleVectorStore` and remote customers APIs, not a local entity repository.

The [gateway POM](../../spring-petclinic-api-gateway/pom.xml) supplies AngularJS 1.8.3, UI Router 1.0.30, Bootstrap 5.3.3, Font Awesome 4.7.0 and marked 14.1.2 through WebJars. UI assets live inside the gateway, not a separate Node application. The optional `css` Maven profile compiles SCSS with libsass-maven-plugin 0.2.29. Existing [design tokens](../../design-system/README.md) remain review input, not an instruction to restyle the app.

## Requests and user flows

[Gateway routes](../../spring-petclinic-api-gateway/src/main/resources/application.yml) remove two URL segments and use discovery-backed `lb://` destinations:

| Browser prefix | Service | Native resource contract |
|---|---|---|
| `/api/customer/**` | customers-service | [OwnerResource](../../spring-petclinic-customers-service/src/main/java/org/springframework/samples/petclinic/customers/web/OwnerResource.java): GET/POST `/owners`, GET/PUT `/owners/{ownerId}`; [PetResource](../../spring-petclinic-customers-service/src/main/java/org/springframework/samples/petclinic/customers/web/PetResource.java): GET `/petTypes`, POST `/owners/{ownerId}/pets`, GET/PUT `/owners/*/pets/{petId}` |
| `/api/visit/**` | visits-service | [VisitResource](../../spring-petclinic-visits-service/src/main/java/org/springframework/samples/petclinic/visits/web/VisitResource.java): GET/POST `/owners/*/pets/{petId}/visits`; GET `/pets/visits?petId=…` accepts a list and returns `{items: …}` |
| `/api/vet/**` | vets-service | [VetResource](../../spring-petclinic-vets-service/src/main/java/org/springframework/samples/petclinic/vets/web/VetResource.java): GET `/vets` with cache name `vets` |
| `/api/genai/**` | genai-service | [PetclinicChatClient](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/PetclinicChatClient.java): POST `/chatclient`, raw string input and string response |

These are the custom REST routes defined in source; framework Config, Eureka, Admin, static resources and Actuator surfaces are additional and depend on configuration. No custom DELETE endpoints are defined in these resources.

1. **Browse and edit clinic data.** The gateway serves [index.html](../../spring-petclinic-api-gateway/src/main/resources/static/index.html). [app.js](../../spring-petclinic-api-gateway/src/main/resources/static/scripts/app.js) configures hash routing (`#!`) and defaults to `/welcome`. The [scripts directory](../../spring-petclinic-api-gateway/src/main/resources/static/scripts) holds routes for `/owners`, `/owners/new`, `/owners/:ownerId/edit`, `/owners/details/:ownerId`, `/owners/:ownerId/new-pet`, `/owners/:ownerId/pets/:petId`, `/owners/:ownerId/pets/:petId/visits`, and `/vets`. Controllers call the prefixes above; request/response changes require checking the corresponding forms and templates.
2. **Owner detail aggregation.** [ApiGatewayController](../../spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/boundary/web/ApiGatewayController.java) implements GET `/api/gateway/owners/{ownerId}`. [CustomersServiceClient](../../spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/application/CustomersServiceClient.java) fetches the owner and pets, then [VisitsServiceClient](../../spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/application/VisitsServiceClient.java) requests visits by pet IDs. The gateway joins on pet ID. Visits failures fall back to empty visits; a successful owner response therefore does not prove visits are available. Customers failure does not use that local fallback.
3. **Chat and tool actions.** [chat.js](../../spring-petclinic-api-gateway/src/main/resources/static/scripts/genai/chat.js) posts a JSON-encoded string to the GenAI route, renders marked HTML and persists displayed messages in browser local storage. The versioned system prompt lives in `PetclinicChatClient`, with chat-memory and logging advisors. [PetclinicTools](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/PetclinicTools.java) exposes list owners, list vets, add owner and add pet; it does not expose a visits tool, despite visits appearing in the system prompt. [AIDataProvider](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/AIDataProvider.java) selects the first discovered customers instance and issues REST requests; vet retrieval uses vector similarity with 20 results, or 50 when no vet criteria are supplied. It is not an exact vet count or authoritative live list.
4. **GenAI startup indexing.** [VectorStoreController](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/VectorStoreController.java) is an application-start event listener, not a REST controller. It loads the bundled [vectorstore.json](../../spring-petclinic-genai-service/src/main/resources/vectorstore.json) if present. Otherwise it fetches `/vets` using the load-balanced WebClient from [AIBeanConfiguration](../../spring-petclinic-genai-service/src/main/java/org/springframework/samples/petclinic/genai/AIBeanConfiguration.java), adds documents to the vector store and saves a temporary file. That path can incur embedding-provider cost. It is not a recurring synchronization job.

No application message broker, scheduled domain job or distributed transaction implementation is present in the enumerated [source inventory](inventory.md).

## Data and trust boundaries

[Customers SQL](../../spring-petclinic-customers-service/src/main/resources/db), [vets SQL](../../spring-petclinic-vets-service/src/main/resources/db) and [visits SQL](../../spring-petclinic-visits-service/src/main/resources/db) contain separate HSQLDB/MySQL schemas and demo seeds. Customers owns `owners`, `pets`, `types`; vets owns `vets`, `specialties`, `vet_specialties`; visits owns `visits`. The [HSQLDB visits schema](../../spring-petclinic-visits-service/src/main/resources/db/hsqldb/schema.sql) stores an integer `pet_id` without a foreign key. In contrast, the [MySQL visits schema](../../spring-petclinic-visits-service/src/main/resources/db/mysql/schema.sql) declares `FOREIGN KEY (pet_id) REFERENCES pets(id)`, and all three MySQL schemas select `petclinic`. The checked-in MySQL path therefore assumes the customers table is available in the same database before visits initialization; physical database isolation is not established by the service boundaries. Do not introduce additional cross-service database coupling as part of this migration. Datasource URLs and initialization settings depend on configuration; SQL files alone do not prove that they execute. HSQLDB schemas contain DROP statements; these fixtures are not production migration or backup procedures. No Flyway/Liquibase migration chain is defined in the POMs.

The repository is a demo topology, not an authenticated production perimeter. The resource classes above do not implement an application authorization boundary. In particular, the wildcard owner segment in pet/visit routes is not an owner-access check; pet update selects the record from the request body's ID. Preserve these existing behaviors in this documentation migration, and assess authorization separately before any public or real-data deployment.

Chat introduces additional boundaries: user text and retrieved owner/vet information enter provider-backed model interactions; registered tools can write customers data; the source contains no explicit per-user conversation identifier in the chat call. Tool methods log owner/pet payloads and the chat configuration enables advisor DEBUG logging. Treat provider input, generated HTML, browser chat storage and operational logs as potentially sensitive. Do not put real personal data into demo smoke checks. These are source observations, not a completed security assessment or a claim about provider retention.

## Configuration, operations and unresolved observations

[Config Server configuration](../../spring-petclinic-config-server/src/main/resources/application.yml) points to external Git on `main`, with a native file backend alternative. The other applications import it optionally in their default configuration and mandatorily under `docker`. Optional import does not supply missing environment-specific ports, discovery or database settings. Review the exact configuration revision used by an environment; application and configuration delivery are separate boundaries.

[Compose](../../docker-compose.yml) declares Config health before Discovery, then requires both before starting the six remaining applications (customers, visits, vets, GenAI, gateway and admin). It also declares Zipkin, Prometheus and Grafana. These are operational dependencies, not additional reactor modules. The [Prometheus scrape configuration](../../docker/prometheus/prometheus.yml), [Grafana provisioning](../../docker/grafana/provisioning) and application `logback-spring.xml` files own monitoring wiring. Customer and visit [metric configuration](../../spring-petclinic-customers-service/src/main/java/org/springframework/samples/petclinic/customers/config/MetricConfig.java) enables timed aspects used by resource annotations; actual metrics delivery must be observed.

Compose uses published application image names without immutable tags; it does not prove those images correspond to this checkout. [Dockerfile](../../docker/Dockerfile) is the shared JAR image definition. No production infrastructure declaration, environment approval policy or production rollback history is included. [Operations](operations.md) owns safe diagnosis and release boundaries.

Existing contradictions and risks remain explicit rather than being silently changed:

- Image `EXPOSE` metadata differs from Compose mappings: gateway declares 8081 versus 8080, vets 8081 versus 8083, and GenAI 8081 versus 8084. The [visits POM](../../spring-petclinic-visits-service/pom.xml) defines `docker.exposed.port`, while the root build consumes `docker.image.exposed.port` with default 9090; its Compose mapping is 8082. These are source-level discrepancies, not observed image metadata. `EXPOSE` is not a listening-port configuration; confirm the effective build and `server.port` before changing either.
- Gateway configuration retries POST once on SERVICE_UNAVAILABLE; no idempotency contract is visible for owner/pet/visit creation. [FallbackController](../../spring-petclinic-api-gateway/src/main/java/org/springframework/samples/petclinic/api/boundary/web/FallbackController.java) handles POST `/fallback` only, although a default circuit breaker applies to other routes too. Failure behavior needs targeted runtime tests before modification.
- `VectorStoreController` calls `ClassPathResource.getFile()` for the bundled vector store. Packaged-JAR startup is not established by an exploded-classpath run; verify it separately. The comment naming H2 data is inconsistent with the checked-in HSQLDB/MySQL fixtures.
- The chat-memory comment says ten messages, but `.order(10)` configures advisor ordering in source, not an explicit memory-capacity setting. No ten-message retention guarantee is documented here.
- Owner telephone constraints differ across consumers: the [browser form](../../spring-petclinic-api-gateway/src/main/resources/static/scripts/owner-form/owner-form.template.html) requires exactly 12 digits, the customers `OwnerRequest` allows up to 12 digits with `@NotBlank`, and the GenAI tool description asks for 10. These source constraints are preserved; changing the accepted input contract requires coordinated form, API and prompt validation.
- Vets caching is enabled by [CacheConfig](../../spring-petclinic-vets-service/src/main/java/org/springframework/samples/petclinic/vets/system/CacheConfig.java) under the `production` profile. That profile name is not evidence of production deployment; actual cache behavior depends on configuration.

For a new domain field, coordinate entity/schema, DTOs, resources, consuming clients and UI together. For gateway routing or resilience changes, start with aggregation/client tests and add a failure-path check that exercises the changed contract. For GenAI changes, prefer fake-provider/service tests before any authorized provider-backed check. Keep new business behavior outside this migration unless a demonstrated blocker requires it.
